# 观澜

币安现货和 USDT 本位永续的公开行情观察台。它把自选交易对、已收盘 K 线、少量固定指标和站内阈值提醒放在你自己的电脑上。

观澜不下单，不读取账户，不保存交易所密钥，也不做回测。指标和提醒只描述已经发生的价格，不构成买卖建议，也不表示能够盈利。

## 这套程序跑在哪

目标机器是你自己的持久 Linux 电脑。

编写和测试用过的云端虚拟机不是那台电脑。虚拟机里的 `127.0.0.1` 只有虚拟机自己能打开，不是给你的链接，也不是公网地址。本仓库没有托管预览，没有部署到公网，也没有购买外部服务。

## 环境

- Node.js 22.5 或更高（使用内置 `node:sqlite`，推荐当前的 Node.js 22）
- npm
- 不需要数据库服务、Redis、Docker 或交易所 API Key

## 启动

在你的 Linux 电脑上：

```bash
node -v
bash scripts/start-local.sh
```

脚本会在缺少 `node_modules` 时执行 `npm ci`，然后构建并只监听 `127.0.0.1:47291`。构建完成后，在这台电脑的浏览器打开：

```text
http://127.0.0.1:47291
```

开发时也可以：

```bash
npm ci
npm test
npm run typecheck
npm run dev
```

观察列表和设置写在 `data/guanlan.sqlite`。重启进程后仍然在。

## 环境变量

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 监听地址。不是回环地址时必须设置口令 |
| `PORT` | `47291` | 端口 |
| `ADMIN_TOKEN` | 空 | 管理口令。本机回环可以留空 |
| `GUANLAN_DB_PATH` | `./data/guanlan.sqlite` | SQLite 文件 |

`127.0.0.1`、`localhost` 和 `::1` 视为本机回环。`0.0.0.0`、局域网地址或其他地址在口令短于 16 位时会拒绝启动。不要把没有口令的管理台暴露到局域网或公网。若前面有反向代理，请由代理终止 TLS，并只允许你自己的网络访问。这是单进程 SQLite，不适合多实例同时写同一个库。

## 数据从哪来

只使用币安公开 REST，不签名，不带密钥。

现货 `https://api.binance.com`：

- `GET /api/v3/ping`，权重 1
- `GET /api/v3/exchangeInfo`，权重 20
- `GET /api/v3/ticker/24hr`，1 到 20 个交易对权重 2
- `GET /api/v3/klines`，权重 2

USDT 本位合约 `https://fapi.binance.com`：

- `GET /fapi/v1/ping`，权重 1
- `GET /fapi/v1/exchangeInfo`，权重 1
- `GET /fapi/v1/ticker/24hr?symbol=`，权重 1
- `GET /fapi/v1/klines`，limit 200 时权重 2
- `GET /fapi/v1/premiumIndex`，权重 1
- `GET /fapi/v1/openInterest`，权重 1
- `GET /fapi/v1/fundingRate?limit=8`
- `GET /futures/data/openInterestHist?period=1h&limit=2`

文档依据是币安现货仓库 `binance/binance-spot-api-docs` 的 `rest-api.md`，以及官方连接器 `binance/binance-connector-python` 里指向 USDⓈ-M 文档的接口说明。本地另设每分钟 1200 的权重预算，低于现货文档示例中的分钟权重和合约常见的 2400。收到 HTTP 429 或 418 时按 `Retry-After` 退避，最多按 30 分钟封顶并在界面说明。资金费率历史和持仓量历史另有每 5 分钟 30 次的本地次数上限。

同一个代码的现货和永续分开保存，例如 `BTCUSDT 现货` 和 `BTCUSDT USDT本位永续`。

## 新鲜度

行情响应带有读取时间和状态：

- `live`：这次或仍在短缓存内的成功读取，可以标成实时
- `stale`：刷新失败，但上次成功读取还在 120 秒内。界面写明已过期，不会标成实时
- `unavailable`：没有可用读数，或旧读数已超过窗口。当前价格位置留空，不把旧价格当成现在的价格
- `demo`：只有你在设置里明确选了示例模式

实时模式失败时不会自动改成示例。示例模式有固定横幅，样例时间是 2024-01-15 09:30:00（上海）。

界面时间用 `Asia/Shanghai`。

## 指标

全部只使用已收盘 K 线。`closeTime` 不早于当前时间的那一根视为未收盘，不进入指标和提醒。样本不够、或分母为 0 时显示“样本不足”或“不可用”，不补 0。

参数固定，不能在界面里改成别的周期。

### EMA20 / EMA60

`k = 2 / (n + 1)`。前 n 根收盘价的算术平均是种子，记在第 n 根。之后：

`EMA_t = 收盘价_t * k + EMA_{t-1} * (1 - k)`

不足 20 或 60 根时，对应均线不可用。若两条都有值，只描述 EMA20 在 EMA60 之上、之下或相等。

### Wilder RSI14

用相邻收盘价差。前 14 个涨跌的简单平均是种子，所以第一颗 RSI 需要 15 根收盘价。之后：

`平均 = (前值 * 13 + 当前涨跌) / 14`

`RS = 平均上涨 / 平均下跌`，`RSI = 100 - 100 / (1 + RS)`。

平均下跌和平均上涨都是 0 时结果不可用。只有平均下跌是 0 且平均上涨大于 0 时，RSI 为 100。

### Wilder ATR14

从第二根开始计算真实波幅，因为需要前一根收盘价：

`TR = max(最高-最低, |最高-前收|, |最低-前收|)`

前 14 个 TR 的算术平均是第一颗 ATR，落在第 15 根。之后：

`ATR = (前值 * 13 + 当前 TR) / 14`

`ATR% = ATR / 该根收盘价 * 100`。收盘价为 0 时百分比不可用。

### 放量比

最近一根已收盘 K 线的成交量，除以它前面 20 根已收盘 K 线的成交量算术平均。当前这根不进入平均。不足 21 根，或平均成交量为 0 时不可用。

### 布林带 (20, 2)

中轨是最近 20 根已收盘收盘价的 SMA。σ 是这 20 个数的总体标准差，分母是 20（ddof=0）。

上轨 = 中轨 + 2σ，下轨 = 中轨 - 2σ。

带宽 = (上轨 - 下轨) / 中轨。界面把带宽乘 100 显示成百分比。中轨为 0 时带宽不可用。不足 20 根时整条带不可用。

收在轨道外指收盘价大于上轨或小于下轨。等于轨道不算在外。

带宽只和上一根已收盘 K 线的带宽比较，标成更窄、更宽或相同。没有隐藏阈值，也没有 %B。

## 提醒

可选条件：已收盘价高于或低于阈值、RSI14 高于或低于阈值、ATR% 高于阈值、放量比高于阈值、收盘价在布林带外。

过期、不可用或指标还没预热时不触发。同一条规则在冷却时间内不重复写入。冷却默认 300 秒，可设 30 到 86400 秒。现货和永续即使代码相同也分开计。删除观察项时，对应规则一起删除。示例模式下的记录带“【示例】”。

## 合约附加信息

永续合约显示 `premiumIndex` 的最新资金费率、下次资金费时间、标记价和指数价，以及 `openInterest` 的持仓量原值。这里不把持仓量换算成名义金额。

持仓量变化只在 `openInterestHist` 至少返回两根可解析的 `sumOpenInterest` 样本时计算，用时间上最后两根相减。否则标为样本不足，不编造前值。前一个样本为 0 时只给出差额，不计算百分比。

## 实时行情是否已在云端验证

没有。2026-11-09 从云端虚拟机访问 `https://api.binance.com/api/v3/ping` 和 `https://fapi.binance.com/fapi/v1/ping`，以及 24 小时行情、资金费率和持仓量，HTTP 状态都是 451，正文为地区限制。程序按这个失败处理，没有改地址，也没有用示例数据冒充实时行情。

你的 Linux 电脑如果能够访问上述官方地址，实时模式会直接请求它们。如果同样被拒绝，界面会显示不可用。
